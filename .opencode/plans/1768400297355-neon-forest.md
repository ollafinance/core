# StakingManager Implementation Plan

This plan covers issues #11, #12, #13 for implementing the StakingManager contract.

## Overview

The StakingManager is responsible for:
- Staking assets with the Aztec rollup using validator keys
- Initiating unstaking (withdrawal from rollup)
- Tracking staked principal and pending unstakes
- Harvesting sequencer rewards
- Managing a queue of validator BLS keys

**Source of truth**: `research/technical/architecture/` spec documents.

## Architecture Context

```
OllaCore --> StakingManager --> AztecRollup (via IStaking interface)
                 |
                 +--> RewardsVault (for harvested rewards)
```

### Roles

| Role | Holder | Permissions on StakingManager |
|------|--------|-------------------------------|
| `CORE_ROLE` | OllaCore | `stake`, `unStake`, `getUnstakedFunds`, `harvestRewards` |
| `STAKING_PROVIDER_ADMIN_ROLE` | Node operator | `addKeysToProvider`, `dripQueue`, set reward address |
| `DEFAULT_ADMIN_ROLE` | Guardian Multisig | Role management |

## Key Integration Points

### Aztec Rollup Interface (IStaking)

```solidity
interface IStaking {
    function deposit(
        address _attester,
        address _withdrawer,
        BN254Lib.G1Point memory _publicKeyG1,
        BN254Lib.G2Point memory _publicKeyG2,
        BN254Lib.G1Point memory _signature,
        bool _moveWithRollup
    ) external;
    
    function initiateWithdraw(address _attester, address _recipient) external;
    function finaliseWithdraw(address _attester) external;
    function claimSequencerRewards(address _sequencer) external;
    function getActivationThreshold() external view returns (uint256);
}
```

## Decision Notes

- **Rewards harvesting**: Will remain a placeholder in this implementation since RewardsVault doesn't exist yet. Full implementation deferred to Milestone 5.

## Implementation Order

1. **Phase 1** (Issue #13): Create all supporting files first:
   - `BN254Lib.sol` - BLS curve point structs
   - `QueueLib.sol` - FIFO queue library
   - `IStakingManager.sol` - Expanded interface with all types/events/errors
   - `IStaking.sol` - Aztec rollup interface
   - `MockAztecRollup.sol` - Mock for testing
   - `StakingManager.sol` - Core contract with access control and placeholders
   - `StakingManager.t.sol` - Unit tests for core functionality

2. **Phase 2** (Issue #12): Implement stake flow:
   - Update `_stakeInternal()` with full logic
   - Add active validator tracking
   - Add stake flow tests

3. **Phase 3** (Issue #11): Implement unstake flow:
   - Add `UnstakeRequest` struct and tracking
   - Update `_unstakeInternal()` with full logic
   - Update `_claimUnstakedFunds()` with full logic
   - Add unstake flow tests

## Verification

After completing all phases:

1. **Unit Tests**: `forge test --match-contract StakingManagerTest -vvv`
2. **Coverage**: `forge coverage --match-contract StakingManager`
3. **Invariant Tests**: Ensure `totalStaked()` always matches sum of active stakes minus pending unstakes
4. **Integration**: Verify OllaCore can call stake/unstake through the manager
